## Private scalar batch + exact-cache development gate

The following additive macro-lot is still **nonrelease** and not frozen
L3-M10 solver implementation. It connects actual, privately captured
Gain+C01 typed jobs to one serial numerical worker with owned background
lifetime, lock-free atomic progress reads and cooperative cancel between
full-prefix DSP evaluations.

- Actual attempted RenderPreview+M19/M20 work is charged to a maximum
  of 800 jobs; preflight and exact completed-cache reuse cost zero.
  Failed render/analyzer work consumes one attempt, never a success.
- Immutable independent REFERENCE M21 cells are captured once on the
  Qt owner. Before any worker execution, Gold's existing canonical
  `gold-file-generation:<M18 epoch>|<provider>|<locator>` identity,
  generation, full-track scope and supported objective values must match.
- A fixed 32-entry *scalar-only* completed cache compares exact PREPARED
  owner, full M18/REFERENCE stamp, frozen registry/backend pointer,
  topology/revision, all typed DSP parameters and block partition.
  A user-supplied fingerprint cannot force a cache hit. No PCM or
  unqualified partial result is cached.
- Multiple Gain proposal value snapshots can be built on the Qt owner
  from **one authenticated M18/Gold admission**, rechecking before and
  after construction. The private registry is shared, not cloned
  hundreds of times. The separate worker never reads mutable QObjects.
- Both candidate score and best-so-far are **private scalar research
  output**; `authorizes_product_publication=false` always. Qt must
  perform live owner revalidation at worker completion. No Project
  persistence, UI AutoMatch button, source mutation, M13 verification
  or M10 objective/tie-order qualification is introduced.

Native focused tests exercise real PCM and M19/M20 with positive
candidate measurements, asynchronous single-flight, pre-cancelled runs,
invalid source/REFERENCE identity, unsupported objectives, duplicate
tickets, cap 800 and strict one-cache-hit accounting.
