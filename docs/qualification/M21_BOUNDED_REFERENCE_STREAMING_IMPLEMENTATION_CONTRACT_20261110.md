Correlation uses 400-ms windows placed at the exact 100-ms `grid100_offset`, centered by the first samples and arithmetic means, then Type-7 p10/p50/p90. - `analysis::measure_basic_level_full_resource` calls M16 True Peak on an *entire owning* buffer. A stream must **not** manufacture an M16 reading or assert that M16 became qualified. Its typed M16 status must remain explicitly unavailable until genuine supported authority exists.

## 3. Memory semantics and performance

The acceptance criterion is bounded **decoded PCM/workspace**, with block allocations and 400-ms stereo windows depending on sample rate, **not the number of WAV frames**. The present result shape retains M19 100-ms gate powers/intervals and M20 correlation grid (approximately one entry per 100 ms); therefore it is not mathematically `O(1)` total-memory with respect to programme duration. Do not claim a strict fixed total-RAM ceiling until the result contract itself is capped or streamed to an external sink. For ordinary long references, avoid any full-track binary64 allocation. Record measured peak RSS, block capacity, and result-memory growth separately.

A practical initial budget is 4096-frame decode blocks, at most 400-ms stereo correlation windows, the fixed M20 FFT ring and PSD vectors, plus the linear-in-duration *output* descriptors. Reusing `WavReader::read_frames` for each correlation window rereads overlaps (roughly 4x those audio frames): benchmark before considering a shared ring-buffer optimization. Preserve deterministic floating-point order rather than trading correctness for one pass.
